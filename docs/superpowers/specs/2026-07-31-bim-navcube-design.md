# BIM NavCube — своя реализация на CSS 3D

Замена встроенного `NavCubePlugin` (xeokit) собственным CSS 3D-кубом.

## Проблема

Встроенный плагин создаёт отдельную WebGL-сцену (`new Scene(viewer, ...)`) со своим
канвасом. На дашборде с несколькими BIM-чартами, которые перемонтируются при
переключении вкладок, контексты конфликтуют: `GL_INVALID_OPERATION: glDrawElements:
Insufficient buffer size` и пустой квадрат в углу. Куб был откачен (см. комментарий
в `useXeokitViewer.ts`).

Ключ: проблема не в геометрии куба, а в том, что он рисуется через WebGL. Своя
реализация решает её только если не заводит второй GL-контекст → CSS 3D.

## Объём

- Кликабельны 6 граней + 8 углов (14 зон). Рёбра — нет.
- Живая синхронизация ориентации с камерой.
- Drag самого куба — нет, только клики.

## Компоненты

**`navCubeMath.ts`** — чистый модуль, без React и xeokit:
- `cameraToCubeRotation(eye, look, up) → {rx, ry, rz}` — векторы камеры → CSS-углы.
- `AREAS` — таблица 14 зон: `{id, label, dir, up}`.

**`NavCube.tsx`** — презентационный компонент. Props: `onSelectArea(areaId)`.
Императивный ref с `setRotation({rx,ry,rz})`. 6 граней в `transform-style:
preserve-3d` + 8 угловых hit-зон. Токены темы, как в `ViewerControls`.

**`XeokitApi`** — два новых метода (реализация в `useXeokitViewer`):
- `onCameraChange(cb): () => void` — подписка на `camera.on('matrix')`, контракт
  как у `onPick`.
- `flyToDir(dir, up): void` — воспроизводит `flyTo` встроенного плагина: центр
  AABB, `dist = diag / tan(fitFOV)`.

## Поток данных

Куб → камера: клик → `onSelectArea` → `BimChart` берёт `dir`/`up` из `AREAS` →
`api.flyToDir`.

Камера → куб: эффект подписывается через `api.onCameraChange`, считает углы и
пишет `transform` прямо в DOM через ref — **мимо React state**, иначе вращение
перерендеривает чарт на каждом кадре.

## Краевые случаи

1. Отписка от камеры должна переживать уничтоженную сцену (как в `onPick`).
2. Эффект подписки гейтится на `ready`: `api` — стабильная ссылка, выставляется
   до наполнения сцены; `flyToDir` читает `scene.aabb`.
3. Куб в правом верхнем углу, ниже строки `RefreshBadge`. Правый нижний занят
   легендой (`ColorLegend`), левый нижний — диагностикой, верх по центру —
   тулбаром. `pointer-events` только на гранях, чтобы не перехватывать
   вращение модели.

## Тесты (без WebGL)

- `navCubeMath.test.ts` — канонические положения камеры → углы; все 14 зон дают
  нормализованные ненулевые `dir`.
- `NavCube.test.tsx` — клик по грани/углу → `onSelectArea` с верным id.
- `BimChart.test.tsx` — клик по зоне → `flyToDir`; размонтирование → отписка.
